# 2026-11-01 Mac 安装器修复与恢复记录

## 确认的缺陷

旧 Mac 启动器将 mkdtemp 返回的指针带出 Swift withUnsafeMutableBufferPointer 的有效生命周期，之后才转换为字符串。普通测试未开启优化，正式程序使用 -O；在优化构建下路径可能损坏或为空，产生 INSTALL_RESOURCES。空的文件路径还可能被 URL 解释为当前工作目录，旧清理代码因此具有误删工作目录的严重风险。

## 本次测试影响

本次运行旧源码的优化回归测试时，原 image-response-fix 工作树和 Documents/image2-mcp 主仓库目录先后消失。检测到后立即停止旧版测试，并退出旧应用。没有使用真实 API 密钥、修改真实 Codex 配置或发起收费生图请求。

## 已完成的恢复

- 主仓库从 origin/main 恢复到原 e1b9b27，并恢复原未跟踪的 GitHub-independent-install 设计文档。
- 开发源码在 macos-resource-fix 工作树中重建，分支为 codex/macos-launcher。来源包括会话中的完整 review diff、按时间保存的补丁和源码写入记录，以及原安装包中的最终安装脚本。
- 原 offline-install 工作树的工作文件仍在，已另外归档，并重建 Git 关联。它的原本地提交对象和索引状态不可恢复，当前关联以 main 为基线，工作文件保持原样。
- Mac 源码和测试尽量按原记录恢复；更新签名测试的旧公钥未找到，使用原测试生成器重新生成匹配的测试签名和公钥。生产更新公钥未替换。
- 原 baac2d4 及其他未推送的 Git 对象、完整本地提交历史未能恢复。重建后的源码会以新的本地提交保全，不能视为原提交链已经找回。
- 原生成包由本次 0.4.2 构建替代；旧应用仅保留为 disabled 恢复副本，请勿再运行。

## 0.4.2 保护措施

mkdtemp 结果在借用闭包内立即转换为独立字符串。暂存路径必须是指定父目录下、名称符合规则的绝对路径；目录归属和权限经验证，清理时再次核对设备与 inode 身份，拒绝删除替换后的目录或符号链接。

测试增加 -Onone 与 -O 双模式、200 轮分配压力、工作目录保留标记、替换目录和符号链接保护。打包流程直接运行已编译应用的无密钥 --verify-resources 自检，再验证实际 app/DMG 的版本、资源清单、签名和隔离安装。
