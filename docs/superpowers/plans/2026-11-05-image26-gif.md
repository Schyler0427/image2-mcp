# Image2.6 and GIF Implementation Plan

> **For agentic workers:** Use test-driven development with independent review before packaging. The user has approved execution in this existing isolated worktree.

**Goal:** Add explicit Image2.6 models and animated GIF generation while preserving the original default and independent credential routing.

**Architecture:** Extend the existing Image2 version mapping and generation request. Keep GIF validation/persistence in a focused internal file, expose fields through unified and legacy MCP generation, and preserve native installer structure.

**Tech Stack:** Go, MCP Go SDK, standard-library GIF decoder, Bash/PowerShell installers, Swift/AppKit macOS launcher.

## Global Constraints

- Ordinary images default to Image2 2.0. Explicit image2.6 selects Sunburst; explicit image2.6-flare selects Flare. No automatic model/provider fallback.
- Image2 and Gemini use their own existing dedicated credential. Do not read or modify actual secrets during automated tests.
- GIF generation without an explicit model/version selects Image2.6 Flare; explicit model selections are never overridden; generation only. Defaults: auto size, 9 frames, 200 ms. Limits: 2–64 frames, 20–2000 ms; 32 million cumulative canvas pixels before full decode.
- Preserve GIF bytes through Base64 and URL paths. Preserve ordinary PNG behavior when new fields are omitted.
- Release 0.4.3; online download pins remain v0.4.0. Preserve prior macOS resource/cleanup safety fixes and native Chinese controls.
