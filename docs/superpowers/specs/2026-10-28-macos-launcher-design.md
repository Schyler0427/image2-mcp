# macOS launcher design

The user requests a Mac counterpart to the finished Windows launcher. Continue the already authorized product design: native double-click window, two new independent provider keys on each install/change, offline installation, automatic architecture choice, explicit signed update download, and the existing Image2 default. No further product decision is needed.

Deliver `SchylerAI-Image2-mcp.app` inside a DMG named `SchylerAI-Image2-mcp-macOS.dmg`. The app main executable is universal arm64/x86_64 and includes complete offline arm64 and amd64 MCP packages. A Mac user opens the DMG, drags the app to Applications and opens it, enters Image2 and Gemini keys in password fields and installs. Existing backend and installer version0.4.0 stay unchanged, as this adds platform packaging without a protocol release. Target macOS12 or later, subject to successful native builds.

Use Swift/AppKit, Foundation and CryptoKit only. Keep GUI, installation and update code separate. Reuse the existing Bash offline bootstrap transaction, package manifest validation, local MCP handshake, backup and rollback; never change a real installation in tests. Do not place keys in args, child env, logs, update requests or resources. Validate each key nonblank, single-line/NUL-free and <=1024 UTF-8 bytes; write Image2 newline Gemini newline once to stdin. Never terminate an installer once the transaction starts; disable install/update/close during it and wait for commit/rollback.

The Mac update endpoint is https://api.schyler.top/image2/releases/latest/launcher-macos.json. Reuse the existing Ed25519 public key and canonical signing fields in Go's existing signer, accept only same-host HTTPS and the exact versioned Mac DMG path, verify signature/version/architectures, bounded size and SHA256 before retaining/opening the new DMG. Never follow redirects or reuse API cookies/keys. Checking and downloading are user clicks; local offline installation does not require updates. Do not deploy the update host in this task.

UI text is Chinese with clear Image2/Gemini labels and the model-routing reminder. No API keys are prepopulated or fetched from existing settings. Output labels and install feedback remain key-safe. Successful install asks to restart Codex/open a new task. Both fields clear when installation begins.

There are no Developer ID signing identities on this Mac. Ad-hoc sign for bundle integrity and local testing, explicitly label delivery as not Developer ID signed/not notarized. Do not remove quarantine, disable Gatekeeper, or claim unrestricted launch on other Macs. Publish a notarization-ready build/signing path and document the remaining publisher prerequisite.

Verification: isolated native Swift core tests for key validation/environment/stdin/transaction result, native update fixtures/signatures/bounds/no credentials, complete Go and installer regressions, universal binary architecture checks, resource hash tamper refusal, native current-Mac packaged install against an isolated HOME, GUI launch/window check without paid APIs or altering real Codex configuration, DMG mount/content/signature/hash checks. Intel execution and remote update deployment cannot be claimed from cross-builds/local fixtures.
